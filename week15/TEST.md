# 테스트 결과

단계마다 테스트 내용, 입력, 기대 결과, 실제 결과, 통과 여부를 적는다.

## 1단계: Flask 뼈대와 사진 올리기 화면 (F1)

### 1-A. 자동 테스트 (Flask test client, 2026-11-17)

서버를 띄우지 않고 Flask의 `test_client()`로 요청을 보내 확인했다.

| 번호 | 테스트 | 입력 | 기대 결과 | 실제 결과 | 통과 |
| --- | --- | --- | --- | --- | --- |
| 1-1 | 첫 화면 | `GET /` | 200 응답 | 200 | O |
| 1-2 | 모바일 화면 설정 | 첫 화면 HTML | `viewport` 메타 태그 있음 | 있음 | O |
| 1-3 | 카메라 바로 열기 | 첫 화면 HTML | 카메라 입력에 `capture="environment"` | 있음 | O |
| 1-4 | 앨범 고르기 | 첫 화면 HTML | 사진 입력 2개 (카메라, 앨범) | 2개 | O |
| 1-5 | 버튼 크기 | CSS `min-height` | 모두 48px 이상 | 48, 54px | O |
| 1-6 | 글자 크기 | CSS `font-size` | 모두 16px 이상 | 처음 14·15px 있음 → 고친 뒤 16, 17, 28px | O (수정 후) |
| 1-7 | 사진 없이 보내기 | 빈 POST | "사진을 먼저 골라 주세요" | 안내 문구 표시 | O |
| 1-8 | 카메라 칸으로 사진 전송 | 4032×3024 JPEG (186KB) | 파일 이름·형식·크기 표시, 서버 로그 출력 | `IMG_0001.jpg, image/jpeg, 191,141 bytes` | O |
| 1-9 | 앨범 칸으로 사진 전송 | 카메라 칸 비우고 앨범 칸에 JPEG | 앨범 사진을 받음 | `album.jpg` 받음 | O |
| 1-10 | 너무 큰 파일 | 21MB 파일 | 413 응답 + "20MB 이하" 안내 | 413, 안내 문구 표시 | O |

### 1-B. 직접 확인 (해야 할 것)

| 번호 | 테스트 | 방법 | 기대 결과 | 실제 결과 | 통과 |
| --- | --- | --- | --- | --- | --- |
| 1-11 | 기기 모드 화면 | 크롬 개발자 도구 → 기기 모드 (목록에 iPhone 12 Pro가 없어 iPhone 16 Pro 크기로 확인) | 화면이 축소되지 않고 버튼이 손가락 크기 | 제목·설명·미리보기 칸이 화면 폭에 맞게 보이고, "카메라로 찍기"·"앨범에서 고르기"·"재료 인식하기" 버튼이 화면 폭 가득, 손가락으로 누르기 충분한 높이로 보임. 사진을 고르기 전 "재료 인식하기"는 꺼진 색(회갈색)으로 표시됨 | O |
| 1-12 | 미리보기와 전송 | 기기 모드에서 "앨범에서 고르기"로 PNG 사진을 고르고 "재료 인식하기" 누르기 | 미리보기가 보이고 "재료 인식하기" 버튼이 켜짐, 누르면 서버로 전송 | 버튼이 켜져 전송됨. "사진을 받았어요" 화면에 `스크린샷 2026-11-17 153357.png`, `image/png`, `464 KB` 표시 | O |
| 1-13 | 서버 로그 | 사진 올리기 후 터미널 확인 | `[1단계] 사진 받음: ...` 출력 | `[1단계] 사진 받음: 스크린샷 2026-11-17 153357.png, image/png, 475,273 bytes` 와 `"POST / HTTP/1.1" 200` 출력 (475,273 bytes = 화면의 464 KB와 일치) | O |

- 참고: 로그의 `GET /.well-known/appspecific/com.chrome.devtools.json ... 404`는 크롬 개발자 도구가 자동으로 보내는 요청이다. 이 앱과 관계없고 동작에도 영향이 없다.
